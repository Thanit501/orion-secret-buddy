# ORION Secret Buddy

โปรเจกต์อิสระสำหรับทีม ORION 12 คน ไม่มีการอ้างอิงโค้ด แพ็กเกจ ฐานข้อมูล หรือ environment ของ bn-trip

วันมอบของขวัญ: **ศุกร์ 27 พฤศจิกายน 2569 · 09.30–11.00 น. · ห้อง 4** งบไม่เกิน **300 บาท**

## เริ่มใช้งานในเครื่อง

ใช้ Node.js 24.14 ขึ้นไป

```sh
npm install
cp .env.example .env
```

ตั้ง `ADMIN_EMAIL` เป็นอีเมลผู้จัด และสร้าง `BETTER_AUTH_SECRET` แบบสุ่มอย่างน้อย 32 ตัวอักษรตามคำสั่งใน `.env.example` จากนั้นรัน:

```sh
npm run dev
```

เปิด http://localhost:3012 ระบบสร้างตาราง SQLite และตาราง Better Auth ให้อัตโนมัติ

ค่าเริ่มต้น `MAIL_MODE=outbox` เป็นการทดสอบในเครื่องเท่านั้น อีเมลและ OTP ถูกเขียนใน `data/outbox/` ไม่ส่งอีเมลจริง ไม่แสดง OTP ในเว็บ และไม่เปิดให้ดาวน์โหลดโฟลเดอร์นี้จากเว็บ เมื่อยังไม่ตั้ง SMTP ให้เปิดไฟล์ outbox ในเครื่องเพื่ออ่านรหัสทดสอบ ผู้จัดเข้าระบบก่อนเพื่อบันทึกรายชื่อสมาชิกจริง

## วิธีจัดกิจกรรม

### ข้าม OTP เพื่อทดสอบในเครื่อง

ตั้ง `DEV_SKIP_OTP=true` ใน `.env` แล้วเริ่มเซิร์ฟเวอร์ใหม่ หน้าเข้าใช้งานจะแสดงเมนูเลือกบัญชีผู้จัดและสมาชิกที่บันทึกไว้ ไม่ต้องรับอีเมล ผู้จัดเพิ่มรายชื่อครบ 12 คนก่อน จากนั้นออกจากระบบเพื่อสลับเป็นสมาชิกแต่ละคนได้ โหมดนี้จำกัดที่ localhost และเซิร์ฟเวอร์ปฏิเสธการเริ่มทำงานหากเปิดร่วมกับ production ปิดด้วย `DEV_SKIP_OTP=false` แล้วเริ่มใหม่เพื่อกลับไปใช้ OTP ตามเดิม

## ส่งต่อให้ผู้พัฒนา

- โค้ดเป็น JavaScript ESM: Express + Better Auth + SQLite บน Node.js 24 ไม่มี build step
- `src/app.js`: auth, API และสิทธิ์ผู้ใช้ / `src/store.js`: รายชื่อและการจับคู่ / `src/server.js`: environment และการส่งอีเมล
- `public/`: หน้าเว็บ ภาษาไทย CSS และ client JavaScript
- `tests/`: ทดสอบ logic, HTTP auth และโหมดข้าม OTP โดยใช้ฐานข้อมูลในหน่วยความจำ
- เริ่มทดสอบเร็ว: คัดลอก `.env.example` เป็น `.env`, ใส่ secret แบบสุ่ม, ตั้ง `DEV_SKIP_OTP=true`, รัน `npm install` และ `npm run dev` ผู้จัดทดสอบเริ่มที่ `organizer@example.com`
- ปัจจุบันฟอร์มสมาชิกยังบังคับอีเมลแม้ในโหมดทดสอบ งานถัดไปที่ผู้ใช้สนใจคือให้โหมดทดสอบกรอกแค่ชื่อและสร้างบัญชีทดสอบอัตโนมัติ
- ฐานข้อมูลและรายชื่อจริงไม่อยู่ใน repository ต้องเพิ่มสมาชิกเองในเครื่องใหม่ ดูผลตรวจล่าสุดที่ `VERIFICATION.md`

1. ผู้จัดล็อกอินด้วย OTP ของ `ADMIN_EMAIL`
2. ใส่ชื่อกับอีเมลสมาชิกครบ 12 คนและกดบันทึก ถ้าผู้จัดร่วมจับด้วย ให้ใส่อีเมลผู้จัดใน 12 คนนี้ด้วย
3. ส่ง URL เว็บเดียวให้ทีม สมาชิกล็อกอินและกรอกสิ่งที่ชอบ / ของที่ไม่อยากได้
4. ผู้จัดกดสุ่มและยืนยัน ระบบบันทึกผลทั้งหมดใน transaction เดียวและล็อกผลทันที ไม่มีปุ่มสุ่มใหม่
5. สมาชิกเปิดการ์ดของตนเอง ระบบตรวจ session บนเซิร์ฟเวอร์และส่งกลับเฉพาะโปรไฟล์ผู้รับของสมาชิกคนนั้น ไม่รับอีเมลผู้ให้จาก request
6. เปิดการ์ดซ้ำได้ ผลยังเป็นคนเดิม ผู้จัดเห็นเพียงสถานะเปิดการ์ด ไม่มี API รวมคู่บัดดี้

## การส่งอีเมลจริง

ตั้ง `MAIL_MODE=smtp` และ SMTP ของคุณใน `.env` ได้แก่ `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` ระบบใช้ STARTTLS สำหรับพอร์ต 587 หรือ implicit TLS เมื่อ `SMTP_SECURE=true` การส่งต้องใช้ผู้ให้บริการที่อนุญาต sender นั้นจริง ไม่ใส่ secrets ลง Git

โปรเจกต์นี้ใช้ Better Auth Email OTP ไม่ใช่การพิมพ์อีเมลแล้วเข้าได้เลย รหัสหมดอายุใน 5 นาที ผิดได้ไม่เกิน 5 ครั้ง และมี rate limit ในฐานข้อมูล อีเมลนอกรายชื่อไม่ได้รับ OTP

## Deploy

ใช้ Node server หรือ Docker ที่มี **persistent disk** สำหรับ `/app/data` ตั้ง `APP_URL=https://your-domain`, `NODE_ENV=production`, `HOST=0.0.0.0`, SMTP และ secret ให้ครบ ใช้หนึ่ง instance เนื่องจากฐานข้อมูล SQLite เป็นไฟล์ ห้ามใช้ ephemeral filesystem หรือ serverless hosting แบบไม่มี persistent volume ไม่ควรเปิดหลาย replica ที่ถือไฟล์คนละชุด

```sh
docker build -t orion-secret-buddy .
docker run --env-file .env -e NODE_ENV=production -e HOST=0.0.0.0 -p 3012:3012 -v orion-data:/app/data orion-secret-buddy
```

วางหลัง HTTPS reverse proxy ซึ่งต้องส่งต่อ Host/Origin ถูกต้องและไม่ cache `/api/*` ระบบ production ปฏิเสธ outbox และ HTTP URL

## ตรวจสอบ

```sh
npm run check
npm test
```

ทดสอบการสุ่ม 1,000 รอบ, ไม่มีผู้รับซ้ำหรือได้ตัวเอง, ล็อกผลและรายชื่อ, OTP login จริงกับกล่องรับอีเมลทดสอบในหน่วยความจำ, การเข้าถึง admin, cross-origin write, การปลอมอีเมลเพื่อดูคู่คนอื่น และ OTP replay ไม่มีการส่งอีเมลภายนอกในการทดสอบ

## ข้อมูลและข้อจำกัด

- ต้องมีรายชื่อ/อีเมลจริงและตั้ง SMTP ก่อนเปิดใช้กับทีม
- ไม่มีการ reset ผ่าน UI ถ้ารายชื่อผิดหลังสุ่ม ผู้ดูแลต้องแก้เป็นกิจกรรมใหม่อย่างตั้งใจ
- ผู้ดูแลฐานข้อมูลย่อมอ่านผลได้ ระบบซ่อนคู่ระหว่างสมาชิกผ่านสิทธิ์เซิร์ฟเวอร์ ไม่ได้อ้างว่าปิดบังผู้ถือฐานข้อมูล
- สำรอง `data/` อย่างปลอดภัยก่อนย้ายเครื่อง เก็บ `.env` แยกจาก backup ที่แชร์ ห้ามส่งฐานข้อมูลหรือ outbox ให้ทีม
- ไม่มีแพ็กเกจ Google Analytics, tracker หรือบริการฟอนต์ภายนอก
